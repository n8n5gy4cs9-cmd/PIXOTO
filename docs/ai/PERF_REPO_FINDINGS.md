# Repo findings (verified by reading code) - read before P3

- Foundations already written and syntax-checked: `app/core/scheduler.js` (createCoalescer with push/idle/cancel, pickPreviewSize), `app/core/bufpool.js`, `app/core/gpu/context.js` (getGl, program, texture/release, upload, framebuffer, bindSampler, drawFullscreen, readPixels, FRAG_HEAD). Use them; do not rewrite. Fragment shaders passed to `program(name, body)` get `FRAG_HEAD` (version, precision, `in vec2 v_uv; out vec4 o;`) prepended unless they start with `#version`.
- Layer matrix: `model.js` `transformMatrix(t, sw, sh)` scales by `t.width/sw, t.height/sh`. So a smaller proxy canvas shown with the SAME `layer.transform` automatically covers the same area. The preview override therefore only swaps the canvas: in `render.js` `drawPixels` (line ~59) use `const c = layer.preview?.canvas ?? layer.canvas` and `m = layer.preview ? transformMatrix(layer.transform, c.width, c.height) : layer.matrix`. Also pass `c` to `drawDistorted` (check it reads `layer.canvas` size) and `effectsOf` (line ~92, uses `layer.canvas`; keep effects off the proxy or feed the proxy). Other readers (`layer.bounds`, `corners`) keep using the real canvas: correct, same area.
- `Layer.preview` is a plain property (`{ canvas }`), not serialized; add it to the Layer class in `model.js` as `preview = null` and make sure history/clone/save ignore it.
- Pixel get/put: `core/pixels.js` `getData`/`putData`, `makeCanvas`. Use these for CPU paths.
- Service worker: `app/sw.js` has `const VERSION = 'pixoto-cameraraw1'` and a `FILES` array of relative paths, generated by `tools/make-sw.py` (optional). Add `"core/scheduler.js"`, `"core/bufpool.js"`, `"core/gpu/context.js"` and later files in alphabetical order and bump VERSION (e.g. `pixoto-gpu1`). Edit by hand or rerun the script.
- Worker (`workers/compute.worker.js`) already has handlers filter/adjust/inpaint/wand/object/subject; `compute.js` posts WITHOUT a transfer list (R3). Fix: `w.postMessage({...}, [buffer])` and keep the fallback by letting `PreviewSession` re-send from its own `image.data` copy.
- Filters live in `core/filters/filters.js` as `FILTERS` entries with `id`, `params`, run via `runFilter(id, params, data, w, h, env)`. PERF P4.2: list ids with `grep -o "id: '[a-zA-Z]*'" app/core/filters/filters.js`, open each, and tag per-pixel/small-kernel ones `gpu` and neighbourhood-heavy ones (painterly, inpaint) CPU.
- Hotspots to change first: `core/ops/preview.js` `run()` (copy per tick) and `show()` (new ImageData/canvas/`mixBySelection`).
